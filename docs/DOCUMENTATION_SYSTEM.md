# 文档系统职责划分

本项目的文档系统为 **agent 长期记忆**服务：把沉淀的经验、决策理由、已否定路线保存下来，避免重复踩坑。文档与代码冲突时，以可验证的事实（代码、日志、生产实证）为准，并立即修正文档。

## 文件职责

| 文件 | 职责 | 更新时机 |
|------|------|----------|
| `AGENTS.md` | 跨任务长期有效的协作原则与红线，不含项目事实细节 | 原则变化时 |
| `README.md` / `README_CN.md` | 面向用户的项目目标、安装、使用入口 | 稳定入口变化时 |
| `docs/DECISIONS.md` | 架构/设计决策及其**理由**（为什么这样做） | 做出或推翻决策时 |
| `docs/KNOWN_ISSUES.md` | 当前已知的未解决问题、环境约束、历史事故模式 | 发现新问题或问题修复时 |
| `docs/DEAD_ENDS.md` | **已否定**的路线及否定证据（防止重新尝试） | 否决一条路线时 |
| `docs/FILE_MAP.md` | 目录职责、关键文件、高风险改动区域 | 结构变化时 |
| `docs/OPTIMIZATION_PLAN.md` | 下载流水线优化方案记录（2026-05 施工） | 历史档案，冻结 |
| `docs/MR_CLEAN_UPDATE_2026_07_15.md` | MR_Clean 模块更新说明（供引用方参考） | 历史档案，冻结 |
| `docs/DEPLOY_INSTRUCTIONS.md` | 服务器部署/排障步骤 | 部署流程变化时 |

## 写作约定

- 每条经验必须带**日期和实证出处**（生产事故、日志、commit hash），没有证据的经验不写。
- 决策要写**理由**而不只是结论——agent 需要知道边界条件，才能判断旧决策在新场景下是否仍成立。
- 被推翻的路线不删除，移入 `DEAD_ENDS.md` 并保留否定理由。
- 修复一个 KNOWN_ISSUES 条目后：标注修复日期和 commit，保留条目作为事故模式参考。
- 施工日志、一次性任务进度不进任何文档；会话级别的过程记录随会话结束丢弃。
